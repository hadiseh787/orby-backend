# راه‌اندازی Orby روی مک

Git و Node.js نسخهٔ ۲۴ همراه npm باید نصب باشند. نسخهٔ ۲۲٫۱۹ به بالا هم پشتیبانی می‌شود. برای اجرای دموی آماده، نصب جداگانهٔ Angular CLI، PostgreSQL، Docker، Rust یا PowerShell لازم نیست.

در نصب موجود، پوشهٔ پروژه، فایل `.env` و مسیر `.data/postgres` را نگه دارید. اجرای قبلی را متوقف کنید و از فولدر بک‌اند این دستورها را به‌ترتیب اجرا کنید:

```sh
cd /Users/hess/project/orby-backend-clean
npm run local:stop
git pull --ff-only
npm ci
npm run setup:model
npm run setup:testnet
npm run local
```

اگر مسیر پروژه متفاوت است، دستور `cd` را مطابق همان فولدر اجرا کنید. اگر Git به‌دلیل تغییرات محلی به‌روزرسانی را رد کرد، ابتدا آن تغییرات را حفظ کنید؛ حذف دیتابیس یا reset بخشی از راه‌اندازی نیست.

برای نصب تازه:

```sh
git clone https://github.com/hadiseh787/orby-backend.git
cd orby-backend
npm ci
npm run setup:model
npm run setup:testnet
npm run local
```

نشانی برنامه `http://127.0.0.1:4200` است. بک‌اند، فرانت‌اند، دیتابیس، worker و مدل پیکربندی‌شده با همین اجرا بالا می‌آیند. فرانت‌اند در commit مشخص و ثابت دریافت می‌شود. برای اجراهای بعدی فقط `npm run local` را بزنید. توقف با Ctrl+C یا `npm run local:stop` انجام می‌شود؛ داده‌ها و تنظیمات باقی می‌مانند.

## نتیجه‌ای که باید دیده شود

در Settings، اتصال قرارداد باید CONNECTED، آمادگی مأموریت READY و مدل واقعی READY باشد. CONNECTED به‌تنهایی مجوز اجرای مأموریت نیست. بررسی اولیهٔ مدل روی CPU ممکن است چند دقیقه طول بکشد؛ این بررسی واقعاً ساختار خروجی، ارجاع منابع و Revision را اجرا می‌کند.

از شش سناریوی صفحهٔ اول یک نمونه را انتخاب کنید؛ فرم با متخصص و سه منبع همان نمونه پر می‌شود. هشت ایجنت کاتالوگ مسیر اجرا دارند. نمونه‌های ثابت تاریخچه، اجرای زنده نیستند؛ برای اجرای تازه از مسیر کپی استفاده کنید.

برای تسویهٔ واقعی تست‌نت، کیف‌پول تست‌نت تحت کنترل خودتان را با موجودی کافی وصل کنید. توافق، برنامه و سقف escrow را بررسی و سپس امضا کنید. کارمزد، سهم سازنده و بازپرداخت پیش از تأیید تسویه نمایش داده می‌شوند. رسید معتبر باید VERIFIED_CONTRACT_STATE و لینک تراکنش نهایی داشته باشد. موجودی simNEAR پول شبیه‌سازی است و به testNEAR تبدیل نمی‌شود.

راه‌اندازی تست‌نت، حساب‌ها و کلیدهای مستقل را روی همان دستگاه تولید می‌کند. آدرس عمومی قراردادِ شخص دیگر اختیار امضا نمی‌دهد. فایل `.env` و فایل‌های خصوصی `.data/near` را منتشر نکنید. از جایگزین‌کردن `.env` با فایل نمونه و حذف `.data/postgres` خودداری کنید.

## خطاهای قابل رفع

- خطای faucet یا RPC: مرحله و اقدام بعدی در خروجی نوشته می‌شود. همان دستور setup را پس از رفع مشکل دوباره اجرا کنید؛ هویت‌ها و تراکنش‌های تأییدشده حفظ می‌شوند.
- مدل آماده نیست: خروجی `npm run setup:model` را بررسی کنید. نصب دستی رسمی مک در https://ollama.com/download/mac قرار دارد. نصب‌کننده ابتدا Ollama موجود و مسیر اجرایی واقعی آن را شناسایی می‌کند.
- خطای رمز دیتابیس: رمز مربوط به دیتابیس موجود را نگه دارید و تطبیق دهید. حذف پوشهٔ داده یا ساخت رمز تازه روی دیتابیس قبلی راه‌حل نیست.
- محدودیت policy یا وثیقه: تعهدهای باز و موجودی سازنده را بررسی کنید. نصب‌کننده کارهای قبلی یا محدودیت‌های مالک را برای عبور اجباری از تست پاک نمی‌کند.
- Quote مین‌نت: فقط پیش‌نمایش واقعی با `dry:true` است؛ امضا، انتقال وجه و افزایش موجودی ندارد. آدرس‌های معتبر تحت کنترل خودتان لازم است و Quote منقضی می‌شود.

جزئیات پذیرش و محدودیت‌های اثبات‌شده در [گزارش انتشار](PORTABLE_RELEASE.md) ثبت می‌شود. پذیرش روی مک مستقل CI به‌معنای دسترسی از راه دور به مک شخصی یا بررسی دیتابیس شخصی شما نیست. Google Sheets تا تنظیم OAuth غیرفعال می‌ماند.
