# دموی واقعی Orby 1.4 — ۱۴ نوامبر ۲۰۲۶

این نسخه مسیر موجود را تکمیل می‌کند: درخواست کاربر، پیشنهاد توافق قابل‌ویرایش، برنامهٔ مدل و تأیید سقف هزینه، استخدام متخصص، یک بازیابی محدود، خروجی مدل واقعی، تأیید مشتری و تسویهٔ NEAR Testnet. طراحی کلی، وام واقعی، اعتبار پیچیده، TEE، multisig و پرداخت واقعی mainnet اضافه نشده‌اند.

## اجرا روی این سیستم

نسخهٔ فعال در `C:\Projects\Orby` است. دستورها از پوشهٔ `backend` اجرا می‌شوند:

```powershell
npm run local
```

همان launcher، PostgreSQL، API، worker، مدل محلی و Angular را با هم راه‌اندازی می‌کند. توقف: `Ctrl+C` یا `npm run local:stop`. فایل‌های start/stop پوشهٔ قدیمی IDE نیز به همین نسخهٔ فعال هدایت می‌شوند؛ سورس قدیمی حذف نشده است.

مدل واقعی این دستگاه `Qwen2.5-1.5B-Instruct-Q4_K_M` است؛ اجرای CPU با llama.cpp نسخهٔ `b12375` و API محلی سازگار با OpenAI انجام می‌شود. هیچ سرویس OpenAI یا API پولی لازم نیست. دریافت مدل و runtime با SHA-256 منبع اصلی تطبیق داده شده است. مدل و کلیدها در Git قرار ندارند.

## نصب از سورس بدون secret

۱. Git و Node.js 24 همراه npm نصب شوند؛ Node 22.19 نیز پشتیبانی می‌شود. Angular CLI، Docker و سرویس PostgreSQL سراسری لازم نیست.

۲. مخزن backend کلون شود و `npm run local` اجرا شود. launcher فرانت را در commit ثبت‌شدهٔ `workspace.json` دریافت می‌کند، lockfileها را نصب می‌کند، تنظیم محلی و دیتابیس می‌سازد و ۱۰ migration را اجرا می‌کند. هر دو ریپو فعلاً خصوصی‌اند و دسترسی به هر دو لازم است. اگر ZIP هر دو کنار هم باشد، مسیر `--frontend` نیز پشتیبانی می‌شود.

۳. برای نصب مدل واقعی روی Windows x64:

```powershell
npm run local:stop
npm run demo:model:setup
npm run local
```

مدل حدود ۱٫۱۲ گیگابایت است و setup نخست اینترنت و فضای دیسک می‌خواهد. فایل نیمه‌کاره تا قبل از تأیید هش فعال نمی‌شود. setup تنظیمات غیرمحرمانهٔ مدل را در `.env` محلی می‌نویسد. مدل از همان launcher بالا می‌آید؛ ترمینال جدا لازم نیست. روی سیستم‌های دیگر، Ollama و یک مدل نصب و `OLLAMA_MODEL` و `OLLAMA_URL` تنظیم شوند. اجرای Linux/macOS در این تحویل آزمایش نشده است.

۴. تست‌نت واقعی به تنظیمات صاحب قرارداد و signer محدود executor نیاز دارد. `.env.example` نمونهٔ بدون کلید است. اطلاعات خصوصی این دستگاه نباید به clone یا README اضافه شوند. برای استقرار مستقل، بخش Contract build and deployment در README شامل ساخت WASM، بهینه‌سازی، faucet و `near:deploy` است. مالک استقرار خودش باید policy و موجودی testNEAR حساب‌هایش را تأمین کند. توکن‌های تست‌نت ارزش مالی ندارند.

## مسیر «انجام بده → ببین»

۱. در پنل مدیریت، RPC باید `CONNECTED` و مدل باید `READY` همراه نام مدل باشد. صرفاً پر بودن متغیر محیطی، اتصال موفق گزارش نمی‌شود.

۲. کیف‌پول تست‌نت متصل شود → پیام NEP-413 با nonce و حساب در سرور بررسی می‌شود. حساب متصل‌شده با نشست تأییدشده یکی نیست مگر امضا معتبر باشد. کیف‌پول‌های injected استاندارد برای کشف محلی به رجیستری اینترنتی وابسته نیستند؛ انتخابگر کیف‌پول‌های redirect همچنان به رجیستری اصلی SDK و اینترنت نیاز دارد. هیچ رجیستری یا executor خارجی داخل برنامه پین نشده است.

۳. Create a job → بخش Draft an agreement from your goal باز شود؛ هدف وارد و پیشنهاد مدل اعمال شود. متن و معیارها قابل‌ویرایش‌اند؛ منابع و بودجه را خود مشتری بازبینی می‌کند. در تست‌نت، گزینهٔ Agent-managed mission فعال باشد. این مسیر از Brief Writer و یکی از متخصص‌های مجاز موجود استفاده می‌کند؛ طراح گراف آزاد یا جست‌وجوی نامحدود نیست.

۴. برای نمونهٔ ضبط‌شده، سه منبع مثال و بودجهٔ کار ۴ testNEAR استفاده شده‌اند. Publish → مشتری فقط ایجاد توافق را امضا می‌کند؛ هنوز استخدام یا پرداخت انجام نشده است.

۵. Choose a proposal → پیشنهاد Brief Writer در بخش Execution plan انتخاب شود. Generate real mission plan → مدل مراحل محدود را پیشنهاد و متخصص را انتخاب می‌کند. سرور قیمت واقعی ثبت‌شده، policy و سقف خرج را اعمال می‌کند؛ مبلغ مدل مجوز مالی نیست.

۶. پیش از اجرا، هزینه‌ها دیده شوند: award برابر ۴، حداکثر escrow برابر ۴٫۴، شامل ۰٫۴ buffer قابل‌بازگشت. سقف مشتری صریحاً تأیید می‌شود. هزینهٔ متخصص در اجرای ضبط‌شده ۱ testNEAR و از موجودی سازنده است؛ دوباره از escrow مشتری برداشت نمی‌شود. Approve plan and fixed budget → فقط رضایت برنامه ثبت می‌شود؛ امضای تأمین وجه جداست.

۷. برای نمایش شکست، گزینهٔ controlled first specialist check failure پیش از تولید برنامه فعال شود. این عیب، صریح و مخصوص دموی محلی accelerated است؛ ادعای خطای تصادفی مدل نیست. Review funding → مبلغ و سقف gas دیده و سپس با کیف‌پول امضا شوند.

۸. View execution → کار فرعی واقعاً روی قرارداد ساخته و از موجودی سازنده تأمین می‌شود. تلاش اول طبق گزینهٔ دمو رد می‌شود؛ قرارداد نسخهٔ اصلاح را باز می‌کند. فقط یک تلاش اصلاح مجاز است و از همان escrow استفاده می‌کند. timeout نیز نتیجهٔ نامعلوم ثبت می‌کند؛ همان شناسهٔ اجرای مدل کورکورانه دوباره فرستاده نمی‌شود. اگر اصلاح هم ناموفق باشد، کار متوقف و تصمیم مشتری/داوری لازم است.

۹. در حالت accelerated پنجرهٔ بررسی فرزند ۹۰ ثانیه است؛ این انتظار داخل ویدئو حذف یا جعل نشده است. پس از تسویهٔ متخصص، مدل اصلی از شواهد پذیرفته‌شده خروجی نهایی می‌سازد.

۱۰. Review delivered output → متن، ارجاع‌ها و معیارها بررسی شوند. Review settlement → award، کارمزد، دریافتی سازنده و بازپرداخت پیش از تأیید نشان داده می‌شوند. پیش‌نمایش با نسخه و هش خروجی تطبیق دارد و منقضی می‌شود. Approve & settle و تأیید کیف‌پول → تسویهٔ واقعی تست‌نت.

۱۱. Receipt → Build receipt preview و Verify receipt → `VERIFIED_CONTRACT_STATE` و لینک تراکنش‌ها. نسخهٔ خصوصی/حذف‌شده و ZIP شواهد همچنان در دسترس‌اند.

۱۲. View balance از صفحهٔ مشتری → صفحهٔ مشخص موجودی و تاریخچه، با تفکیک مطالبات قرارداد از موجودی خود کیف‌پول. بخش Mainnet top-up preview صرفاً quote واقعی `dry:true` می‌گیرد. شبکه، توکن، مبلغ، دریافتی تخمینی، انقضا و اطلاعات کارمزد دیده می‌شوند؛ آدرس واریز، امضا، انتقال، swap یا افزایش موجودی ندارد.

## شواهد و هزینه‌ها

- `orby-real-mission-1.4.json`: مسیر واقعی، سه تلاش مدل برای دو نسخهٔ متخصص و یک خروجی اصلی، هزینهٔ متخصص بدون افزایش، تسویه‌های قرارداد و هش‌های تراکنش.
- `demo-1.4/`: ویدئوی کامل WebM و تصاویر برنامه، خروجی، پنجرهٔ تسویه و رسید تأییدشده. ویدئو با کیف‌پول توسعه‌ای ثبت شده که پیام‌ها و تراکنش‌های واقعی را با کلیدهای توسعهٔ نادیده‌گرفته‌شده در Git امضا می‌کند؛ امضای انسانی HOT/Meteor ادعا نمی‌شود.
- `orby-intents-safe-mode.json`: quote زنده و عدم تغییر موجودی. نرخ ۲۵ bps فقط تخمین surcharge منتشرشدهٔ درخواست بدون API key است؛ کارمزد کل مسیر محسوب نمی‌شود. هزینهٔ تفکیک‌نشدهٔ provider صفر معرفی نمی‌شود.
- رسید، درآمد سازنده، هزینهٔ تسویه‌شده و escrow متخصص، کارمزد و ماندهٔ پیش از هزینه‌های محاسبه‌نشده را نشان می‌دهد. token usage و زمان مدل ثبت‌اند. API محلی صورتحساب پولی ندارد؛ برق، سخت‌افزار و تخصیص کامل gas قیمت‌گذاری نشده‌اند، بنابراین مانده «سود» نام نمی‌گیرد.

یک اجرای واقعی اولیه، Recommendation دوواژه‌ای تولید کرد و پس از یک اصلاح هم معیار طول را پاس نکرد. این مورد پرداخت اصلی نگرفت و از مسیر عادی قرارداد کامل به مشتری بازپرداخت شد؛ شواهد در `orby-real-model-regression-refund.json` است. قید طول در تولید ساختاریافته و بازخورد خطای قبلی اصلاح شد و اجرای کامل بعدی پاس شد. هیچ خروجی یا چک قبلی برای پاس‌کردن دمو بازنویسی نشده است.

## تست و محدوده

```powershell
# backend، با PostgreSQL در حال اجرا
npm test
npm run test:integration
npm run contract:test
npm run build
npm run backup
npm run backup:verify

# frontend، بعد از آماده‌شدن launcher
$env:PLAYWRIGHT_BASE_URL='http://127.0.0.1:4200'
npm run test:e2e
```

تست‌های دیتابیس، دیتابیس موقت جدا می‌سازند و فقط همان را حذف می‌کنند. تست‌های timeout و HTTP ساختگی از آزمون واقعی مدل/تست‌نت جدا گزارش می‌شوند. محدودیت نرخ API خاموش نشده است. حلقهٔ تست‌نت، شبیه‌سازی، برنامه‌ها و Quality Lab مستقل‌اند تا انتظار RPC، صف simNEAR را متوقف نکند.

ضبط دوبارهٔ سناریوی واقعی اختیاری و مخصوص مالک کلیدهای توسعه است:

```powershell
$env:DEMO_ORIGIN='http://127.0.0.1:4200'
node --import tsx tests/mission-demo-testnet.ts --run
```

این دستور faucet testNEAR مصرف می‌کند و بدون تأییدهای UI، برنامه و کیف‌پول، هزینه ایجاد نمی‌کند. برای داور عمومی، ویدئو و رسیدهای عمومی کافی‌اند؛ کلیدهای توسعه نباید توزیع شوند.

Google Sheets در نبود OAuth با پیام واضح غیرفعال است و این اتصال مانع مسیر اصلی نیست. اینترنت برای RPC، quote و کیف‌پول‌های خارجی لازم است. صحت معنایی همهٔ ادعاهای مدل، audit مستقل امنیت، اجرای مین‌نت، TEE و multisig ادعا نشده‌اند. LICENSE کد موجود است؛ ریپوها خصوصی باقی می‌مانند. انتشار عمومی، پست X و ارسال نهایی فقط با هماهنگی صاحب پروژه انجام می‌شود.
