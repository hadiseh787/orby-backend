# Documentation fixes — 7 November 2026

Reference: [bug and change document](https://docs.google.com/document/d/1YiVYrZaljRfxTBTUaCOB1bmGK0P4zMINKqaWXpAwtFs/edit). The received text is kept in `ORBY_CHANGE_REQUEST_2026-11-07.txt`. Item 1 at the top of the document, about hiding Settings and Trust, was not applied per the user's instruction. The numbers below refer to the document's "Important" and "Minor" sections.

| Item | Result |
| --- | --- |
| Near testnet RPC not configured error | The public testnet RPC address is provided to the connector providers. `NEAR_WALLET_RPC_URL` is independent of the backend RPC so that a possible backend service key is never exposed in the browser. A real connector sandbox test confirms the address is received. |
| Important 1: job deadline | The publication deadline origin remained; in the form, the publication confirmation, the bid and the funding window state explicitly that waiting for a bid also counts against the deadline. Before funding, the actual remaining time and the UTC date are shown. The date sent to the contract is exactly the stored date. An expired job cannot be funded and is removed from the offer list. |
| Important 2: legacy bid | A single dialog detects the job's unit; NEAR converts with 24 digits and legacy USD with 6. A legacy amount is explicitly labeled USD; the display conversion with a fixed rate was removed. A native-only agent is excluded from the USD bid options and the API rejects it as well. |
| Important 3: locked Agent ID | The Agent owner gets a Recover registration button in the PENDING state. The unsigned operation continues with the same request_id; after a definite FAILED with no Agent on the contract, the same ID can be registered again. UNKNOWN or SUBMITTED requires receipt reconciliation. A confirmed Agent is recovered from the contract with a matching owner and manifest hash. |
| Minor 4: login callback | DIRECT mode accepts only the specified callback. Compatibility without a callback is limited to the REDIRECT challenge and receiving the signature from the fragment. One-time nonce, expiry, recipient and the FullAccess key remain mandatory. Details in `SECURITY.md`. |
| Minor 5: rounding and rate | `agentMinimum` is a shared ceil function for manual and automatic bids. On testnet the agent minimum and the legacy rate are read from the contract; the legacy preview carries the same rate and must refresh when the rate changes. The fixed rate remains only in SIMULATION. The USD market rate does not enter settlement. |
| Minor 6: Agent version | Changing only the NEAR price no longer increments the manifest version; an accepted bid stays valid with the earlier price. The fix does not change the contract state layout. |
| Minor 7: start window | The accelerated window is 300 seconds in simulation and in the contract; the normal mode is 600 seconds. The contract child path was aligned as well. |
| Minor 8: price freshness | The fallback without a timestamp was removed and replaced with the Coinbase Exchange ticker, which carries the trade time. Both rate sources treat anything older than 5 minutes, timestamp-less, or from the future as not fresh; the cache keeps the real observation time. |
| Minor 9: preview accounting | A NEAR job has `native-near-v1` and a rate of exactly 1 Q; `fixed-demo-v1` and 5 dollars are not recorded for it. The source is explicitly "no currency conversion". |
| Minor 10: upload | Each account's combined limit across both books is 100 files and 50 MiB of raw content; attached files are also counted. The 25-unused-file cap was kept. A transaction lock keeps concurrent uploads from slipping past the quota. |
| Minor 11: migration 003 | Not removed: it is a historical compatibility migration for databases that ran the earlier 002 draft without a CID. Removing or rewriting an applied migration is inappropriate; the reason for the duplication was recorded. 004 only adds the authentication flow and the quota index. |
| Minor 12: teardown | The worker drains before the app and the pool close; the database is dropped without FORCE after the connections close so that an in-use connection is not severed. |

Other document improvements were also applied: CSP with a nonce is enabled, the preview lifetime is 5 minutes in the backend and the contract, the login input is named `accountId`, and two real simulation sample jobs — one native OPEN and one SETTLED — were added to the repeatable seed. The settled sample goes through the same application financial path and creates no testnet transaction. To gradually break up the files, the security logic, agent registration recovery, the sample seed and the contract amount display were moved into separate modules; a full restructuring of the application was not done.

The final mobile test found a conflict between CSP and Angular's generated inline critical CSS. That optimization loaded the CSS with `media=print` and an inline onload handler, which CSP blocks. In the production build, inlineCritical was disabled; minification is kept and the full CSS loads without an inline handler. The CSP test also checks for the absence of onload and that the real styles are applied.

## Validation

- The Angular build and the backend TypeScript build succeed.
- 10 unit/runtime tests pass, including 10,000 balance-preservation cases and the freshness of both price sources.
- 12 PostgreSQL integration tests pass, including registration recovery, the authentication boundary, USD bids and the upload quota; consecutive runs were checked for teardown errors.
- 10 browser tests cover CSP, nonce rotation, the wallet sandbox running with RPC, and a real USD submission from the dialog to the API.
- The three Rust financial tests pass and the optimized WASM was built with NEAR-compatible settings.
- The testnet contract upgrade was done without creating accounts, seeding, or changing the state layout. A before/after comparison confirmed all 7 jobs and 8 contract balances unchanged: `orby-upgrade-20261107.json`.
- A real browser run through to testnet passed with CSP enabled: agent registration, NEP-413 login, policy and bond, job creation with an attachment, the owner's bid, a price change without a manifest version bump, funding the earlier bid with the five-minute preview, delivery, evaluation, approval, settlement and a successful withdrawal. Job `48292f93-d26f-4186-9525-fb3de9333093` reached SETTLED; the award was 0.1, the refund 0.01, the fee 0.01 and the creator credit 0.09 test NEAR. The receipts are in `orby-browser-testnet.json`.
- A backup taken after the new migration was restored onto a fresh database; tables, attachments, hashes and row counts were verified.

## Delivery scope

Mainnet is not active. The development wallet test uses real signing and a real testnet transaction; personal confirmation in every third-party wallet was not tested. The Ollama model and permanent public IPFS still require separate deployment configuration. The CSP allows HTTPS/WSS and inline styles for wallet compatibility; this is not an independent security audit. No test guarantees the absence of all unknown bugs.
