# بستهٔ مستقل تحویل Orby

وضعیت: طراحی پیشنهادی برای بررسی؛ برنامه و قرارداد هنوز پیاده نشده‌اند. پروژهٔ حقوق و خزانه در این بسته تغییر نکرده است.

ترتیب مطالعه:

۱. فایل `PRODUCT_SPEC.fa.pdf` یا نسخهٔ HTML آن: دامنه، اصلاحات مالی، فیچرها، قرارداد، API، داده، ۴۸ سناریوی پذیرش و برنامهٔ توسعه.

۲. فایل `DESIGN_SYSTEM.fa.pdf`: رنگ، اندازه، اجزا، متن انگلیسی، صفحه‌های اصلی و رفتار responsive.

۳. فایل `design/preview.html`: نمونهٔ تعاملی انگلیسی و کاملاً محلی با شش نما؛ با مرورگر باز شود. هیچ تراکنشی نمی‌فرستد.

۴. پوشهٔ `examples`: پیام‌های نمونه، manifest، قواعد مالی و بردارهای آزمون. پوشهٔ `contracts` شرح ABI دارد، نه قرارداد آمادهٔ استقرار.

منبع قابل‌ویرایش هر سند با پسوند `.md` وجود دارد. فایل‌های CSS و JSON دیزاین‌سیستم در پوشهٔ `design` هستند. فونت فارسی داخل HTML/PDF تعبیه شده است. فایل `FONT_LICENSE.txt` مجوز فونت است.

مبنای تحویل: ابزار رایگان و تست‌نت NEAR؛ UI انگلیسی؛ سند فارسی؛ یک توسعه‌دهنده و امکان کمک نفر دوم. برش اصلی برای ده روز طراحی شده است؛ اعتبار واقعی مرحلهٔ بعد است و زمان کل بیشتر است.

تصمیم‌های مهم: Escrow مرجع دلاری با سقف، نه تضمین دلار؛ داوری AI کمکی؛ مجوز مالی در قرارداد؛ اعتبار با وثیقهٔ جدا؛ شبیه‌سازی با واحد و دفتر جدا. این تصمیم‌ها در بخش ۲ سند محصول نسبت به فایل ورودی توضیح داده شده‌اند.

شروع برنامه‌نویسی پس از پذیرش مبنای طراحی انجام می‌شود. نخست M0 و آزمون signing، ابزار Rust و مدل محلی اجرا شود. دستورهای نصب برنامه که در سند آمده‌اند «قرارداد تحویل آینده» هستند و در این بسته اجراشدنی نیستند.
