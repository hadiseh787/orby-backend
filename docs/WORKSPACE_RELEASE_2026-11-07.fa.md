# Orby 1.2 — اجرای درخواست کامل تغییرات

تاریخ: ۷ نوامبر ۲۰۲۶. مرجع این نوبت [نسخهٔ ذخیره‌شدهٔ داک](ORBY_CHANGE_REQUEST_2026-11-07_workspace.fa.txt) است. کاربر اجرای همهٔ اصلاحات و بخش توسعه را خواست. استثنای قدیمی «مورد ۱ را نادیده بگیر» مربوط به نسخهٔ قبلی داک بود؛ مورد ۱ فعلی، حفظ پیش‌نویس، اجرا شده است. گزارش انتهای داک دربارهٔ دستگاه دیگری، مدرک آزمایش این دستگاه محسوب نشده است.

## بهبودهای جریان سفارش

- کپی کار قبلی و قالب شخصی از کار موفق. قالب بریف و معیارها را نگه می‌دارد؛ فایل، منبع و بودجهٔ قدیمی خودکار منتقل نمی‌شوند.
- انتخاب دو یا سه پیشنهاد و مقایسهٔ پیش‌نمایش مالی واقعی سرور، زمان تحویل، خروجی و سابقهٔ تکمیل؛ انتخاب همچنان به مرور پرداخت می‌رود.
- نمایش منبع و عبارت شاهد کنار ارجاع؛ نقل‌قول فقط وقتی متن در منبع وجود داشته باشد. ثبت «شاهد کافی نیست» و درخواست اصلاح روی ردیف/توصیهٔ مشخص.
- خروجی‌های تغییرناپذیر شماره‌دار، نمایش بخش تغییرکرده، یک دور اصلاح مطابق قرارداد، و تأیید دقیق نسخهٔ بررسی‌شده. کپی و دانلود متن خوانا همراه evidence فنی.
- صندوق اقدام از وضعیت فعلی ساخته می‌شود: پیشنهاد تازه، خروجی منتظر بررسی، اصلاح یا مهلت نزدیک. پس از تسویه از صندوق خارج می‌شود؛ رخدادهای فنی اعلان جدا تولید نمی‌کنند.

## امضا و قرارداد

پیش از هر تراکنش کاربر، حساب، قرارداد، اثر اقدام، مبلغ دقیق و گس نمایش داده می‌شود؛ لغو بدون ارسال به کیف پول ممکن است. عملیات معلق به حساب، محیط و قرارداد محدودند و بعد از رفرش قابل ادامه‌اند. هش نامطمئن جدا از هش اثبات‌شده نگه‌داری می‌شود. امضاکننده، قرارداد، روش، آرگومان، گس و مبلغ با پیشنهاد تطبیق داده می‌شوند. موفقیت به نهایی‌شدن RPC وابسته است؛ برداشت علاوه بر آن، callback موفق همان قرارداد و request ID را لازم دارد.

صف شبیه‌سازی درخواست تست‌نت را lease یا مصرف نمی‌کند. اختلاف زنجیره‌ای به پروندهٔ برنامه منتقل می‌شود. تأیید `approve_delivery` به نسخه و هش متصل است؛ `request_revision` بازخورد را متعهد می‌کند. `release_unused_bond` فقط وثیقهٔ آزاد را به موجودی قابل برداشت منتقل می‌کند و وثیقهٔ رزروشده را دست نمی‌زند.

قرارداد موجود `af-contract-1793954330698.testnet` با چیدمان دادهٔ ثابت ارتقا یافت. هر ۸ کار و ۸ موجودی قبل از ارتقا حفظ شدند؛ [مدرک ارتقا](orby-workspace-upgrade.json) و [اثر انگشت استقرار](orby-deployment.json). نسخهٔ ساختار قرارداد همچنان ۲ است؛ افزودن روش‌ها به تغییر چیدمان نیاز نداشت. استقرارهای قدیمی برای سه روش جدید باید با همین کد ارتقا یابند.

## آزمایش و شواهد

- بیلد تولیدی Angular و TypeScript موفق؛ هشدار CommonJS کانکتور کیف پول باقی است.
- ۱۳ تست واحد/runtime و ۲۳ تست یکپارچه در دیتابیس موقت مستقل موفق؛ شامل تسویه، هم‌زمانی، مالکیت، نسخهٔ تأیید، برنامه‌ها، پرداخت همهٔ شرکت‌کنندگان، دانش خصوصی، صندوق اقدام و جداسازی صف‌ها.
- ۳ تست مالی native قرارداد موفق؛ تست‌های مالی Node و Rust شامل ۱۰٬۰۰۰ حالت پایستگی هستند.
- هر ۱۹ تست مرورگر پاس شد؛ تصاویر دسکتاپ و موبایل نیز بازبینی شدند. مرور امضا و بازیابی آن با fixture مشخص، و جریان مالی واقعی با harness مستقل تست‌نت بررسی شد.
- گردش مرورگر تا تست‌نت با امضاهای NEP-413 و RPC واقعی موفق: ثبت ایجنت، policy، وثیقه، سفارش و فایل، پیشنهاد، تغییر قیمت بدون ابطال پیشنهاد، funding، تحویل، اصلاح روی زنجیره، نسخهٔ ۱، تأیید همان نسخه، تسویه، آزادسازی وثیقهٔ آزاد و برداشت با callback. ۱۱ تراکنش کاربری، جدا از تراکنش‌های worker؛ [رسیدهای عمومی](orby-browser-testnet.json).
- هفت migration اعمال شد. snapshot سازگار PostgreSQL به دیتابیس تازه بازگردانده شد؛ وابستگی جدول‌ها، محتوای فایل، تعداد ردیف‌ها و sequenceها تأیید شدند.
- راه‌اندازی نسخهٔ ۱٫۲ از آرشیو فقط سورس و بدون `.env`، فرانت، وابستگی یا دیتابیس پاس شد: دریافت فرانت pin‌شده، نصب هر دو lockfile، ساخت، ایجاد دیتابیس و هفت migration؛ سپس سفارش تازه با دانش خصوصی تا تحویل worker و تأیید/تسویه اجرا شد. [مدرک اجرای تمیز](orby-clean-start-1.2.json).
- تست HTTP اتصال Google شامل state یک‌بارمصرف متصل به مرورگر، توکن رمزگذاری‌شده، عدم نوشتن قبل از تأیید، حفظ ردیف قبلی و تطبیق append نامطمئن است. این fixture است؛ اتصال حساب واقعی Google ادعا نمی‌شود.

اجرای سوئیت کامل مرورگر با رعایت محدودیت نرخ API انجام می‌شود؛ سرور برای تست محدودیت خود را از دست نمی‌دهد. نتایج نهایی مرورگر در [گزارش راستی‌آزمایی](VERIFICATION.md) ثبت شده‌اند.

## اجرا و موارد نیازمند تنظیم مالک

شروع محلی تغییری نکرده: در پوشهٔ backend فرمان `npm run local` یا فایل `start-local.cmd`، هر دو برنامه و PostgreSQL و worker را راه می‌اندازد. Git و Node.js با npm پیش‌نیازند؛ دسترسی هر دو ریپوی خصوصی لازم است. وابستگی به فولدر تاریخی پروژه وجود ندارد. داده و کلیدها وارد Git نشده‌اند؛ frontend در `workspace.json` به commit مشخص pin می‌شود.

برای Google زنده، مالک باید client ID/secret و رضایت حساب Google را تنظیم کند؛ بدون آن فقط این اتصال غیرفعال است. برای LLM، Ollama و مدل جداگانه لازم است؛ اجرای پیش‌فرض دمو قطعی و محدود به دادهٔ ورودی است و صحت مستقل حقایق را تضمین نمی‌کند. Credit همچنان شبیه‌سازی است و قرارداد وام ندارد. Mainnet غیرفعال است، ارزیابی امنیتی مستقل انجام نشده، و Linux/macOS روی این دستگاه اجرا نشده‌اند. این آزمایش‌ها اثبات نبود همهٔ باگ‌های ممکن نیستند.
